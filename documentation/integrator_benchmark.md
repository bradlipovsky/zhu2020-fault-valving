# Time-integration comparison

The initial independent implementation used ARS(2,2,2), with one full step and
two half steps per error estimate. Its main and validation datasets were still
incomplete when a fourth-order alternative was tested. Those exploratory files
were archived locally, and none enters the final panel pipeline.

ARK4(3)6L[2]SA uses six mechanical stages, compared with six stages for the
step-doubled ARS method. Both solve pressure implicitly with the same nonlinear
finite-volume operator. A fully coupled temporal refinement gives errors
5.83e-9, 4.23e-10, 2.63e-11, and 1.62e-12 at steps approximately 80, 40, 20,
and 10 thousand seconds. These are maximum errors scaled by the physical
error scales, against a 2500 s calculation. This demonstrates fourth-order
convergence in that smooth verification problem, not across arbitrary ruptures.

For a direct runtime check, both methods advanced the same independently
generated rupture checkpoint for one second, on 32768 cells. At tolerance
0.001, ARS used 495 accepted steps and 121.3 s wall time; ARK4 used 175 steps
and 49.2 s. A tighter ARK4 calculation at tolerance 0.0001 used 289 steps and
56.2 s. Maximum differences from the tight solution were:

| Field | ARS(2,2,2) | ARK4 |
|---|---:|---:|
| Slip (m) | 8.37e-6 | 5.09e-6 |
| State psi | 1.39e-4 | 8.45e-5 |
| Normalized k* | 8.08e-6 | 4.97e-6 |
| Pressure (Pa) | 4.48e-4 | 1.42e-4 |

The checkpoint, source hash of its generating solver, wall times, and archived
process identifiers are described in `integrator_benchmark.json`. These are
local runtime measurements on shared hardware, not general performance claims.
The smaller errors and shorter runtime motivated the method change. Final
figure data are regenerated from initial conditions using ARK4 exclusively.

The comparison driver can be used on any checkpoint generated by this new
implementation (never on an authors' checkpoint):

```
cmake --build build --target integrator_compare
cp data/baseline/checkpoint.bin .tmp/comparison.bin
build/integrator_compare configs/baseline.cfg .tmp/comparison.bin 2 1
build/integrator_compare configs/baseline.cfg .tmp/comparison.bin 4 1
```

Each command writes its final state beside the copied checkpoint and reports
accepted/rejected steps and wall time. Copying first ensures both methods use
the same state even if the generating process is still running. The ordinary
verification suite runs without a checkpoint or any archived state.
